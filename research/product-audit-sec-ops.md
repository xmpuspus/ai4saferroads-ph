## Detail: the XSS injection points (every one)

OSM-derived, attacker-editable strings reaching an HTML sink without escaping:

1. `build/web/index.html:237` — `${p.name}` into popup `setHTML`. **Attacker-controlled** (OSM `name`). HIGH.
2. `build/web/index.html:237` — `${p.highway}` into popup `setHTML`. Pipeline-controlled (constrained to the `DRIVABLE` enum at `sss_pipeline.py:49-52`), so practically not injectable today, but still unescaped into HTML.
3. `build/web/index.html:241` — `${p.why}` into popup `setHTML`. Pipeline-controlled free text (`sss_pipeline.py:112-131`); not attacker-editable today but it is unescaped free text in an HTML sink.
4. `build/web/index.html:140` — `${r.name}` into `#roads.innerHTML`. **Attacker-controlled** (OSM `name`). HIGH, auto-fires on load.
5. `build/web/sim.html:56` — `${CORR.name}` into `#sub.innerHTML`. Curated `corridor.json` today; latent (MEDIUM).

Not injectable: `index.html:212` builds `<option>` values from `cities.json` (local, curated). All numeric interpolations (`sss`, `v_posted`, `v_safe`, `gap`, `fatal_reduction_pct`, counts) are numbers from the pipeline and safe.

One `esc()` helper applied at points 1, 4, and 5 (and defensively 2–3) closes the whole class. Add input sanitization of `name` in `sss_pipeline.py` for defense in depth.

## Detail: live CSP assessment

Live value (verified, identical to `vercel.json:12`):

```
default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'self';
script-src 'self' 'unsafe-inline' https://unpkg.com;
style-src 'self' 'unsafe-inline' https://unpkg.com;
img-src 'self' data: blob: https:; connect-src 'self' https:;
worker-src 'self' blob:; child-src 'self' blob:; font-src 'self' data:; manifest-src 'self'
```

- **Allows what's needed:** unpkg for maplibre JS/CSS; `img-src https:` for Esri/CARTO raster tiles + `data:`/`blob:` for canvas/og; `connect-src https:` for the geojson/font fetches and tile XHRs; `worker-src/child-src blob:` for maplibre web workers; `font-src data:` for the demotiles glyphs. The app loads and renders under this policy — functionally correct.
- **Blocks what it should:** `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'self'` are all good and tight.
- **The hole:** `script-src ... 'unsafe-inline'`. Combined with `img-src https:` / `connect-src https:`, an injected inline handler both executes and exfiltrates. So against the two HIGH XSS findings the CSP is non-mitigating. `connect-src https:` and `img-src https:` are also broad (any HTTPS host) — fine for availability, but they widen the exfil channel once script runs.
- **Net:** good header hygiene overall, but the CSP cannot be cited as compensating control for the XSS. Fix escaping first; drop `'unsafe-inline'` (needs externalizing the inline script) second.

## Scores

**Security: 58 / 100.**
Two HIGH auto-/hover-triggered DOM-XSS findings from unescaped OSM `name`, with a CSP that doesn't contain them (`'unsafe-inline'`), plus missing SRI on a CDN dependency. Offsetting positives: no committed secrets, keyless tile/Overpass usage, loopback-only dev server, and a genuinely strong baseline header set (HSTS/HSTS-preload, XFO+frame-ancestors, nosniff, referrer-policy, permissions-policy). The escaping fix is small and would move this to the low-80s; dropping `'unsafe-inline'` + SRI would reach the high-80s.

**Operational: 64 / 100.**
Single-command deploy (`vercel --prod`), stdlib-only pipeline, loopback dev server, pinned CDN version, correct gitignore, and good baseline headers are real strengths. Dragged down by: `make e2e` actually failing while the README badge claims it passes (a false-green gate that also misdescribes the sim as three.js), no version control and no CI, a missing `LICENSE` file the README links to, and a non-deterministic live-Overpass build with no snapshot/version stamp so README counts can silently drift. Fixing the e2e/three.js drift, adding `LICENSE`, `git init` + a minimal CI that runs `make e2e` and a header check, and stamping the OSM data date would move this into the low-80s.
